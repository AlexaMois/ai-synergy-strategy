# Редизайн главной V2 — безопасная подготовка без публикации

## Подтверждение безопасности (проверено)

- Продакшен www.aleksamois.ru деплоится workflow-ом `.github/workflows/deploy.yml` **только по push в ветку `main`** репозитория.
- Работа в Lovable идёт в отдельной ветке `edit/...`: обычные правки и черновики не пишут в `main`, значит GitHub Pages пересборку не запускают.
- Боевой сайт меняется только при явной публикации (accept + publish) — эти шаги выполняются только по прямой команде пользователя.

## Рекомендуемый путь: черновик (draft), а не remix

1. Создать черновик «Главная V2» текущего проекта (свой предпросмотр, свои правки, изолированный backend-стек).
2. Вести редизайн главной страницы целиком внутри черновика: новые тексты, структура, макеты — без изменения формы заявок, маршрутов лидов и логики захвата.
3. Проверять результат в предпросмотре черновика; продакшен-сайт при этом недоступен для изменений физически.
4. Публикация — отдельный шаг: после явного «принять черновик» и «опубликовать». Только тогда изменения уйдут в `main` и GitHub Pages пересоберёт боевой сайт.

## Почему не remix (несмотря на предпочтение)

- Remix изолирован и безопасен, но его изменения нельзя автоматически вернуть в основной проект — перенос V2 потом придётся делать вручную.
- В remix копируется код, но не данные: портал, заявки и статистика будут пустые, проверять реалистичные сценарии неудобно.
- Черновик даёт ту же изоляцию от продакшена, но с возможностью однобнойного переноса через accept.

## Что НЕ делаем

- Никаких правок кода основного проекта, публикаций, accept черновиков и изменений форм/заявок в этом шаге.
- Никаких команд, пишущих в `main` репозитория.
